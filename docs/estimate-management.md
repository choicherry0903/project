# 견적 초안 관리

PPT 추출본 `docs/screen-design-source.txt`의 17~18쪽을 기준으로 구현했습니다.

- `/estimates`: 현장명 검색, 상태 필터, 20개씩 목록 조회. 현장 상세의 견적 탭에서는 해당 현장의 견적만 표시합니다.
- `/estimates/new`: 현장 선택, 유효기한·공사 범위·제외 공사 입력, 항목 추가·삭제, 등록 자재의 이름·단위·판매 단가 복사.
- `/estimates/{id}`: 저장된 항목과 서버 계산 금액 조회.
- `/estimates/{id}/edit`: 초안 수정. 기존 견적의 현장은 변경하지 않습니다.
- `/estimates/{id}/delete`: 삭제 확인 후 POST로 초안을 목록에서 제외합니다. DB 기록과 버전 번호는 보존합니다. 복원 UI는 아직 없습니다.

자재·인건비·철거·운반·기타 항목을 입력합니다. 수량은 소수점 두 자리, 금액은 원 단위이며 항목 금액과 세액은 반올림합니다. 할인은 항목 합계 이내여야 하며 총액 상한은 999,999,999원입니다. 브라우저의 표시 총액을 서버 계산과 비교하고 차이가 있으면 저장을 거부합니다.

미입력 항목도 초안으로 저장됩니다. 수량 또는 단가가 비어 있으면 해당 행의 계산 금액은 0원이며 빈 상태를 별도 플래그로 보존합니다. 항목명·단위가 없는 행도 수량·단가가 입력되어 있다면 초안 계산에 포함합니다. 무료 사유는 입력할 수 있으며 확정 시 필수 검증은 후속 단계입니다.

자재 정보는 견적에 복사합니다. 이후 자재 수정·삭제로 기존 견적의 명칭과 판매 단가가 변하지 않습니다. 수량은 직접 입력하며 실측의 자동 반영과 롤 수량 계산은 후속입니다.

ADMIN/OFFICE만 이용할 수 있고 모든 조회·저장은 로그인한 업체 범위에서 검사합니다. 수정·삭제는 DRAFT만 허용하며 화면의 버전을 검사합니다. 항목만 수정해도 견적 버전이 증가합니다. 신규 저장은 요청 키를 사용해 같은 요청의 재시도를 중복 저장하지 않으며 현장 잠금으로 견적 버전 충돌을 막습니다.

실제 DB는 앱 재시작 시 Flyway V12(견적 초안 관리)와 V13(미완성 항목 보존)으로 컬럼·인덱스가 추가됩니다. 이미 적용된 V12는 원본 체크섬을 유지합니다. `supabase,shared` 프로필은 마이그레이션을 실행하지 않으므로 담당자가 먼저 적용해야 합니다. 기능 검증은 H2 테스트·메모리 데모에서 수행했습니다. V12 체크섬 복원 후 실제 Supabase DB의 V12·V13 적용 기록과 미완성 항목 컬럼 두 개도 읽기 전용으로 확인했습니다.

견적 확정·복제 개정·PDF 출력·계약 연결은 다음 단계입니다.

검증: 전체 40개 테스트 통과. 기존 V12 체크섬 유지 및 V12 → V13 업그레이드 테스트 포함. PPT 예시 합계 2,178,000원, 미완성 초안, 중복 요청, 동시 수정 충돌, 삭제 버전 검사, 삭제 후 버전 번호 보존, 타 업체·작업자 접근 차단, CSRF, 확정 견적 수정·삭제 차단, 날짜·0% 세율 수정 폼 유지.

일부 Windows 환경에서 Mockito 자동 부착이 멈추면, 설치된 Mockito JAR를 테스트 JVM의 `-javaagent`로 지정해서 실행할 수 있습니다. 이번 검증에는 다음 명령을 사용했습니다.

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-25.0.4.1'
$env:MAVEN_USER_HOME = 'C:/workspace/interior_cms/.m2'
./mvnw.cmd '-Dmaven.repo.local=C:/workspace/interior_cms/.m2/repository' '-DargLine=-javaagent:C:/workspace/interior_cms/.m2/repository/org/mockito/mockito-core/5.20.0/mockito-core-5.20.0.jar' -B -ntp test
```
