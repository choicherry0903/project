# 자재 품목 관리

- 목록: `/materials`, 등록: `/materials/new`, 상세: `/materials/{id}`, 수정: `/materials/{id}/edit`.
- 목록에서 품명을 누르면 상세로 이동합니다. 수정·삭제 버튼은 상세 화면에 표시하고 저장 후 상세 화면으로 이동합니다. 목록의 검색 조건은 데스크톱에서 한 줄로 배치하며 검색·초기화 버튼은 그 아래 가운데에 표시합니다.
- ADMIN/OFFICE 권한으로 로그인한 사용자가 자기 회사의 자재만 관리합니다.
- 품명과 두 분류는 필수이며 제조사, 사이즈, 색상은 선택 입력입니다.
- 장소는 `MaterialCategories.ALL`, 품목은 `MaterialCategories.ITEMS`에서 독립적으로 관리합니다. `category`와 `subcategory` 코드로 저장하며 서버에서는 각각 유효한 코드인지 확인합니다. 두 분류는 자유롭게 조합할 수 있습니다.
- 등록·수정 화면에서는 장소와 품목의 전체 항목을 표시합니다. 목록에서도 각각 선택해 검색하며, 전체 선택 시 해당 분류의 필터를 해제합니다.
- 제공된 발주서 25장의 분류를 참고했습니다. 화장실의 벽체·바닥타일은 개별 품목으로 나누고, 주방 상단장·하단장도 각각 등록할 수 있습니다.
- 기존 자재는 그대로 유지합니다. 새 분류와 사이즈 컬럼은 V9 마이그레이션으로 추가되며, 기존 품목 수정 시 분류를 선택합니다.
- 수정·삭제는 version으로 동시 변경을 확인합니다. 발주에서 참조하는 품목은 외래 키 제약으로 삭제를 차단합니다.

## R2 이미지 저장

- `.env` 또는 서버 환경 변수에 `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`를 설정합니다. Endpoint에는 `/roofandwall` 같은 버킷 경로를 붙이지 않습니다.
- 자재당 이미지 한 장을 `materials/{companyId}/{UUID}.{확장자}`로 저장합니다. DB가 해당 이미지와 자재를 연결합니다. 공통 `ImageStorage`와 `ImageUpload.Folder`를 다른 메뉴에서도 사용할 수 있습니다.
- 파일 선택은 최대 1개로 제한하며, 여러 파일을 담은 저장 요청도 서버에서 거부합니다. 새 이미지를 저장하면 기존 이미지 한 장을 교체합니다.
- JPG/PNG/WEBP, 최대 10MB, 최대 2,500만 화소이며 실제 이미지 내용을 서버에서 확인합니다. 원래 파일명과 브라우저 MIME은 저장 경로를 결정하는 데 사용하지 않습니다.
- 등록·수정 폼에서 파일을 선택하면 저장 시 업로드됩니다. 수정에서 새 이미지를 선택하면 교체하며, 현재 이미지 삭제를 체크하면 저장 시 연결을 제거합니다. 새 파일이 없으면 기존 이미지를 유지합니다.
- 목록 썸네일과 상세·수정 화면에 이미지를 표시합니다. `/materials/{id}/image`는 회사·권한 확인 후 5분짜리 R2 서명 URL로 이동합니다. 버킷 공개 설정과 브라우저 업로드용 CORS 설정은 필요하지 않습니다.
- DB에는 만료되지 않는 object key만 저장합니다. 업로드 실패 시 DB 변경은 롤백되고 기존 이미지는 유지됩니다.
- 교체·삭제한 파일은 DB 변경이 확정된 후 `storage_deletions` 큐에서 정리합니다. 30초마다 최대 20개를 처리하며 오류는 재시도합니다. DB 저장 실패나 프로세스 중단으로 남은 새 업로드는 한 시간 후 정리 대상이 됩니다.
- V10 마이그레이션으로 `materials.image_key`와 정리 큐 테이블을 추가합니다. 실행 중인 앱은 재시작하여 새 설정과 의존성을 반영하세요.

## 검증

`scripts/run-local.ps1 -Task test`로 자재 CRUD, 분류 코드, 회사별 접근 범위, CSRF, 이미지 업로드·유지·교체·삭제, 업로드 실패 롤백과 파일 검증을 테스트합니다. R2 인증 값이나 만료되는 서명 URL은 로그에 출력하지 않습니다.
