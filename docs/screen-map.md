# 세 화면의 초기 구성

인터뷰와 실제 자료 확인 전의 가정입니다. 업무 순서와 항목은 업체 검토 후 변경합니다.

| 메뉴 | 경로 | 초기 구성 |
| --- | --- | --- |
| 고객·현장 목록 | /projects | 현장명·고객·담당자·진행 상태·다음 할 일 목록, 검색·상태 필터·등록 버튼 자리 |
| 현장 상세 | /projects/detail | 기본 정보, 상담 이력, 파일·사진, 다음 할 일 |
| AI 상담 정리 | /consultations/ai | 현장 선택, 상담 원문, 공사 범위·예산·희망 일정·고객 요청·추가 확인 사항 |

메뉴는 위 세 개뿐입니다. 현장 상세는 데이터 조회가 없는 독립 미리보기 화면입니다.
진행 상태 후보는 상담 → 현장 확인 → 견적 → 계약 → 시공 → 완료·AS입니다.
후보를 선택하거나 상태를 변경하는 기능은 없습니다.

## 구현 경계

현재 구현은 GET 화면 경로와 공통 메뉴 이동, HTML/CSS뿐입니다.
등록·검색·조회·수정·저장·업로드·AI 호출, DB 연결, 메시지 수집은 구현하지 않았습니다.
모든 업무 입력과 버튼은 비활성 상태이며 현장 데이터 및 AI 결과는 비어 있습니다.

## 이후 검토할 사항

1. 실제 견적·상담 자료로 목록과 상세의 필수 항목 확인
2. 고객과 현장의 관계, 진행 상태, 담당자 구조 확정
3. 고객·현장 기록과 상담 원문의 저장 및 접근 권한 설계
4. AI 정리 초안, 원문 대조, 직원 수정·확인 후 저장 흐름 설계
5. 파일 저장과 외부 API 전달 범위 설계
